# Keymaps

Leader is **Space**. Local leader is unset.

Three ways to browse them live:

- `<leader>ch` — NvCheatsheet (grid of every binding)
- `<leader>wk` — which-key query for a prefix
- `<leader>wK` — which-key, all keymaps

## Where they come from

| Source | File | In repo |
|---|---|---|
| NvChad defaults | `~/.local/share/nvim/lazy/NvChad/lua/nvchad/mappings.lua` | no |
| Your overrides | `lua/mappings.lua` | yes |
| Dashboard buttons | `lua/chadrc.lua` (`M.nvdash.buttons`) | yes |
| Plugin defaults | LSP (Neovim builtin), treesitter textobjects, conform, nvim-dap, vim-tmux-navigator | no |

Later maps win, so a repo map overrides an NvChad one on the same key.

The tables below are **generated** from the live keymap table, so they cannot
drift from the config. Regenerate after changing any mapping:

```sh
nvim --headless -c "lua dofile('nvim/.config/nvim/scripts/dump-keymaps.lua')" -c 'qa!'
```

The generated `Source` column is `repo` when a mapping's key literal appears in
this config's Lua files, and `default` otherwise (NvChad, a plugin, or Neovim
itself). Lua-defined mappings expose no usable script id, so this is source
search, not runtime attribution.

## Notes and known oddities

- **`<C-h/j/k/l>` are overloaded by mode.** Insert = cursor motion, and
  `<C-j>`/`<C-k>` also drive completion selection while the menu is open.
  Normal and terminal = tmux pane navigation. Consequence: `<C-h>` no longer
  backspaces in insert mode (use `<BS>`).
- **Normal-mode `<C-h>`/`<C-l>` are tmux navigation**, so they replace NvChad's
  `<C-w>h` / `<C-w>l` window maps. Splits still work: `TmuxNavigate*` moves to an
  nvim window when one exists in that direction and only forwards to tmux when
  there is none.
- **`<C-j>`/`<C-k>` select completions** because cmp replaces NvChad's cursor
  maps on `InsertEnter` and keeps the old maps as the fallback
  (`cmp.core:prepare` → `keymap.listen`). With the menu closed they fall through
  to cursor down/up.
- **`<leader>m` is both a mapping and a which-key prefix** for the Markdown maps.
  Vim waits `timeoutlen` before firing it, since it cannot know whether a second
  key is coming.
- **Dashboard keys are buffer-local.** `ff`, `fo`, `fw`, `ma`, `th`, `ch` and
  `<CR>` exist only in the nvdash buffer; `j`/`k` there are guarded against the
  upstream E5108 crash (see `lua/autocmds.lua`).
- **Formatting is split across two systems.** `<leader>fm` uses conform (NvChad
  default, LSP fallback) plus `spring-javaformat` for Java; none-ls handles
  prettierd/black/gofumpt but is ft-gated to `python` and `go`, and
  format-on-save is off. See `AGENTS.md`.
- **Java test keymaps do not exist.** `<leader>dgt`, `<leader>dgl` and
  `<leader>dpr` are Go/Python-only. See `AGENTS.md`.
